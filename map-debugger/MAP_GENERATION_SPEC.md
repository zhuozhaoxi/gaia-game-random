# HEXFIELD 地图生成规则与实现说明

更新日期：2026-09-26

本文档记录当前游戏地图的组成、随机生成规则、数据模型和合规验证标准。后续修改地图生成逻辑时，应同步更新本文档。

相关文件：

- 统一生成与校验核心：`../js/gaia-map-core.js`
- 正式页面 SVG 渲染：`../js/gaia-map-generator.js`
- Debugger 应用入口：`index.html`
- 板块格子类型数据：`../js/r2-boards.js`
- 游戏板块图片：`../doc/gaia/map/`

## 0. 单一规则源

正式页面和地图 Debugger 必须共用 `window.GaiaMapCore`：

- `GaiaMapCore.generate()` 负责一次性生成 R2、三角板和特殊单格布局。
- `GaiaMapCore.validate()` 负责校验完整布局是否满足本文件中的规则。
- `GaiaMapCore.compactLayout()` 将完整布局转换为 Debugger 的持久化格式。
- `GaiaMapCore.specialsToRecord()` 将特殊单格数组转换为 Debugger 使用的坐标字典。

`gaia-map-generator.js` 只负责正式页面的 SVG 渲染；`map-debugger/index.html` 只负责编辑、交互、持久化和调试展示。两处不得再复制随机生成、旋转求解或舰队距离算法。修改生成规则时只改 `gaia-map-core.js`，并同步更新本文档。

## 1. 地图总体结构

- 坐标系统：六边格轴向坐标 `Q / R`。
- 地图方向：平边朝上，整体地图在基础坐标上旋转 30° 显示。
- 有效地图格：224 格，仅保留实际被游戏板块覆盖的格子。
- 游戏板块：共 28 块。
  - R2 大板块：10 块，每块半径为 2，共 19 格。
  - 三角板块：8 块，每块由 3 个相连六边格组成。
  - 特殊单格板块：10 块。
- 默认六边格的填充和边界均为透明，仅在悬停、选中或 Debugger 高亮时显示轮廓。

## 2. R2 大板块

### 2.1 板块与位置

R2 板块编号为 `01–10`，每张地图使用全部 10 块，每块只出现一次。

固定的 10 个中心槽位依次为：

```text
(0, 0)
(5, -4)
(-5, 4)
(-1, 5)
(4, 1)
(9, -3)
(10, -8)
(6, -9)
(1, -5)
(-4, -1)
```

位置随机规则：

1. 从 `01–04` 中随机抽取两个不同板块。
2. 将这两个板块随机放入中心槽位 `(0, 0)` 和 `(5, -4)`。
3. 剩余 8 个 R2 板块随机填入其余 8 个槽位。

### 2.2 方向随机

- 每块 R2 板块独立抽取旋转步数 `0–5`。
- 实际旋转角度为 `旋转步数 × 60°`。
- 板块图片、局部格坐标和行星标注必须使用同一旋转结果。

### 2.3 行星数据

- 行星信息以板块自身的局部轴向坐标保存，不写死为大地图绝对坐标。
- 数据文件：`../js/r2-boards.js`。
- 放置板块时，使用“板块局部坐标 + 板块旋转 + 板块中心坐标”计算世界坐标。
- 因此板块随机换位和随机旋转后，仍可准确获得每颗行星的位置和种类。

当前共有 7 种参与同色相邻校验的标准行星，每种均为 6 个，总计 42 个：

```text
红、蓝、黄、棕、橙、白、黑
```

R2 板块同时以相同的局部坐标方式记录 12 个超维星球和 7 个盖亚星球。这两类信息用于展示和调试，不参与标准行星的同色相邻校验。

### 2.4 同色相邻合规规则

最终地图中，不允许两个同种类行星位于相邻六边格。

相邻关系使用轴向坐标的 6 个方向判断：

```text
(+1, 0)  (+1, -1)  (0, -1)
(-1, 0)  (-1, +1)  (0, +1)
```

生成后的处理流程：

1. 汇总全部 R2 板块上 42 个行星的世界坐标。
2. 检查是否存在同色相邻行星。
3. 若存在冲突，只重新随机旋转冲突涉及的板块。
4. 每轮旋转后重新执行完整合规检测。
5. 随机修正长时间未收敛时，使用旋转组合搜索作为兜底。
6. 只有冲突数量为 0 时，地图才算生成成功。

## 3. 三角板块

### 3.1 板块与槽位

- 三角板编号为 `11–18`，每张地图使用全部 8 块，每块只出现一次。
- 8 块三角板随机分配到 8 个固定外围槽位。
- 槽位自身保留基础方向，用于与地图外形对齐。

### 3.2 正反面随机

每块三角板放置后，独立随机选择：

- 实心面：`编号-实心.png`
- 空心面：`编号-空心.png`

### 3.3 方向随机

- 每块三角板独立抽取旋转步数 `0–2`。
- 随机附加旋转角度为 `旋转步数 × 120°`，即 `0° / 120° / 240°`。
- 最终图片角度为 `槽位基础方向 + 随机附加旋转角度`。
- 随机旋转步数独立写入地图配置，支持刷新、撤回和导入导出。

### 3.4 线下摆放文字

- 正式页面在每个三角板外围显示 `编号-空心/实心`，用于线下快速摆放。
- 上下两侧文字保持水平，左右两侧文字旋转 90°。
- 当前字号为 `9px`，字重为 `500`，颜色为淡青色 `#587b95`。
- 文字属于 SVG 覆盖层，并会包含在分享图片中。

### 3.5 格子类型数据

- 三角板的小行星、源行星和超维星球按“板块编号 + 正反面 + 板块局部角度”保存在 `../js/r2-boards.js` 中。
- 局部角度为 `0° / 120° / 240°`，放置时会同步应用槽位基础方向和板块随机旋转。
- 因此三角板换位、翻面或旋转后，Debugger 仍可正确计算元素的世界坐标。

## 4. 特殊单格板块

10 个特殊单格槽位固定为：

```text
(-3, 1)
(-2, 3)
(1, 2)
(-1, -2)
(3, -1)
(6, -2)
(8, -5)
(7, -7)
(4, -6)
(2, -3)
```

每次重新生成时，随机放置以下素材：

- 舰队板块：4 个，各使用一次。
- 源行星：1 个。
- 小行星：4 个。
- 空板块：1 个。

源行星和小行星的格子类型直接绑定在对应特殊板块图片上，随图片的随机位置同步更新世界坐标。

舰队距离规则：

- 任意两个舰队板块之间的六边格距离必须大于 3。
- 4 个舰队之间需要两两满足该条件。
- 先选择满足距离约束的 4 个槽位组合，再随机分配 4 张舰队图片。

## 5. 重新生成地图

点击“重新生成地图”按钮后，一次操作完成：

1. 保存当前状态到撤回历史。
2. 随机分配 R2 板块位置。
3. 随机并修正 R2 板块方向，直至行星相邻冲突为 0。
4. 随机分配三角板位置、实心/空心面和 `0–2` 旋转步数。
5. 随机生成满足舰队距离约束的特殊单格布局。
6. 重新渲染板块图片和格子元数据。
7. 保存新地图配置到浏览器本地存储。
8. 若 Debugger 已开启，刷新地图元素坐标列表并清除旧高亮。

正式页面的骰子按钮和 Debugger 的“重新生成地图”按钮都调用 `GaiaMapCore.generate()`，因此两处使用完全相同的随机与合规规则。

重新生成操作支持 `Ctrl+Z` 或 `Command+Z` 撤回。

## 6. Debugger 模式

Debugger 开启后：

- 按 7 种标准行星、小行星、源行星、超维星球和盖亚星球分组显示。
- 每项显示所属 R2、三角或特殊单格板块，以及当前大地图 `Q / R` 坐标。
- 坐标根据当前板块位置、正反面和旋转动态计算。
- 点击“高亮全部”可以一次显示当前地图上的所有已录入标注，便于目视检查遗漏。
- 点击分类标题会同时高亮该类型的所有坐标，再次点击取消高亮。
- 点击坐标后，地图自动移动至目标格并显示黄色高亮。
- 重新生成地图时，Debugger 列表同步更新，不保留旧坐标高亮。

## 7. 配置与持久化

浏览器本地存储：

```text
hexfield-notes-v1       文字标注
hexfield-specials-v1    特殊单格布局
hexfield-map-layout-v1  R2 与三角板布局
```

当前地图布局配置结构示意：

```json
{
  "version": 2,
  "generatedAt": "ISO-8601 time",
  "r2": [
    { "number": "1", "rotation": 3 }
  ],
  "triangles": [
    { "number": "11", "side": "实心", "rotation": 2 }
  ]
}
```

说明：

- `r2` 数组下标对应固定 R2 中心槽位，`rotation` 范围为 `0–5`。
- `triangles` 数组下标对应固定三角槽位，`rotation` 范围为 `0–2`。
- 导出文件格式当前版本为 `9`，包含文字标注、特殊单格布局及完整地图布局。
- 旧版三角板配置没有 `rotation` 时，按旋转步数 `0` 兼容读取。
- `GaiaMapCore.generate()` 返回的完整布局为版本 `1`，额外包含每个板块的坐标、三角槽位数据和 `specials` 数组。
- Debugger 保存的紧凑布局为版本 `2`；该格式只存随机结果，固定坐标从公共核心常量恢复。

## 8. 生成结果验收清单

每次修改随机算法后，至少检查：

- [ ] 地图仍为 224 个有效格和 28 个图片板块。
- [ ] R2 编号 `01–10` 各出现一次。
- [ ] `(0, 0)` 与 `(5, -4)` 上的 R2 均来自 `01–04`，且不重复。
- [ ] 每个 R2 旋转步数均为 `0–5`。
- [ ] 42 个行星全部存在，7 种颜色各 6 个。
- [ ] 同色相邻行星冲突数量为 0。
- [ ] 三角板编号 `11–18` 各出现一次。
- [ ] 每块三角板的实心/空心素材有效。
- [ ] 每块三角板旋转步数均为 `0–2`，最终角度正确。
- [ ] 4 个舰队各出现一次，且任意两个舰队距离大于 3。
- [ ] 重新生成可被撤回。
- [ ] 刷新页面后地图布局不变。
- [ ] 导出再导入后布局不变。
- [ ] Debugger 坐标与当前随机布局一致。
- [ ] 正式页面和 Debugger 均加载 `gaia-map-core.js`，且随机按钮没有私有生成算法。
- [ ] “生成分享图片”成功，三角板文字包含在导出图片中。

建议回归命令：

```bash
node scripts/audit-map-randomness.js 2000
```

审计结果中的 `invalidLayouts` 和 `generationErrors` 必须均为 `0`。
